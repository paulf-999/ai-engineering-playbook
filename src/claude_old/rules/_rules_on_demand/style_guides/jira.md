# 🎫 Jira style guide

**Purpose:** standards for a team's Jira tickets, covering fields, ticket structure, sprint assignment and business value.

## 🏗️ Core principles

- **Completeness** — all required fields set before a ticket enters the sprint: priority, story points, assignee, sprint, description
- **Scannability** — bullet points throughout; no prose walls in description or acceptance criteria
- **Consistency** — standard components, labels, and description structure on every ticket
- **Traceability** — a Claude-created label on every Claude-authored ticket, named in your Jira values; enables hygiene checks and filtering

## 📚 Read on demand

- **Read on demand:** `_rules_on_demand/style_guides/jira/_ticket_conventions.md`, in your Claude config directory, when writing a ticket's summary, description or acceptance criteria.
- **Read on demand:** `_rules_on_demand/style_guides/jira/_field_standards.md`, when setting a ticket's fields, components or labels.
- **Read on demand:** `_rules_on_demand/style_guides/jira/_definition_of_ready.md`, before moving a ticket into a sprint.
- **Read on demand:** `_rules_on_demand/style_guides/jira/_sprint_planning.md`, when choosing a ticket's sprint, epic or story points.
- **Read on demand:** `_rules_on_demand/style_guides/jira/_business_value.md`, when writing the Business Value tab.
- **Read on demand:** `_rules_on_demand/style_guides/jira/_jira_values_template.md`, when `_local/jira_values.md` is missing, for the values to collect.
